# Strata — the company brain that knows when it's wrong

> Built for **Graph Hacks: Context for AI Agents** (WeMakeDevs × FalkorDB).
> **Tracks entered: Company Brain · Agent Memory and Coordination**

<!-- GIF of the live drift moment goes here: docs/live-drift.gif -->

**Links:** live demo — _added at submission_ · demo video — _added at submission_ · blog post — _added at submission_

Company knowledge does not just go missing. It goes **wrong**. A decision is reversed in a Slack thread; the onboarding doc, the service README and three open tickets still describe the old decision; a new engineer follows them and breaks something. Search tools find documents. None of them know a document has become wrong.

Strata is a company brain on **FalkorDB** that keeps every decision as a *versioned layer* (like rock strata): old decisions are closed, never deleted. Paste one Slack message that reverses a decision and Strata

1. closes the old decision and the facts it established (`valid_to`), keeping the history,
2. finds every doc and open ticket that asserts or cites the old knowledge,
3. resolves who is accountable for each one, and
4. drafts the fix. **A human approves or rejects each one. Nothing changes without a click.**

Then drag the time slider and the answer to "why?" changes between last month and today.

> **The demo company is synthetic.** Northwind Labs (25 people, 5 teams, 8 systems, ~40 docs, ~60 tickets, ~270 messages, ~50 PRs, 12 decisions) is generated by `data/generate.py` from a fixed storyline. No real or private data is used anywhere. See [Honesty](#honesty).

## How each Company Brain focus point is served

| Focus point | Feature | Graph templates that power it |
|---|---|---|
| Knowledge from docs, tickets and chats in one graph | One graph of `Doc`, `Ticket`, `Message`, `PR`, `Chunk`, `Decision`, `Claim`; semantic entry points | `find_entry_points_vector` (Q1), `ingest_decision` |
| Who owns what, and who knows what | **Who Knows**, bus factor, knowledge bridges, informal teams | `who_knows_activity` + `pagerank` + `betweenness` (Q7), `bus_factor` (Q9), `informal_teams` (Q8), `route_to_owner` (Q5) |
| Tracing decisions back to their source | **Ask Why** with lineage and evidence path | `why` (Q2), `decisions_by_ids` |
| Keeping knowledge current as things change | **Drift Inbox** + time travel | `supersede` (Q3), `whats_stale` (Q4), `create_drift_task` (Q6), `approve_doc` / `approve_ticket`, `why` with `$t` |
| Answers with clear sources | Every sentence carries evidence ids; no evidence means "I don't know" and shows what was searched | `why`, `find_entry_points_vector`, `person_work` |
| (Track 02) Remember across sessions | Per-user graph `strata_user_<id>` | `p_record_question`, `p_record_shown`, `p_last_shown` |
| (Track 02) Share state between agents | Ingestor → Steward → Concierge hand off through `Task` nodes; restart resumes | `create_pipeline_task`, `handoff_task`, `agent_timeline`, `resume_tasks` (Q11) |

## Architecture

```
            ┌──────────────────────────── Next.js web app ────────────────────────────┐
            │ Chat (sourced answers) │ Graph panel (path highlight, dim = closed)      │
            │ Time slider │ Drift Inbox │ Who Knows │ Agents timeline │ Ingest box     │
            └───────────────────────────────────┬─────────────────────────────────────┘
                                                │ REST
            ┌───────────────────────────────────▼─────────────────────────────────────┐
            │                           FastAPI backend (Python)                       │
            │  Ingestor ─writes─┐    Concierge (routes to vetted templates, composes   │
            │  (LLM extraction) │    answers from graph results, cites evidence)       │
            │                   ▼                                                      │
            │            ┌──────────────┐     Steward (stale detection, owner routing, │
            │            │ GraphService │◀─── LLM only drafts the diff text)           │
            │            │ the only     │                                              │
            │            │ FalkorDB I/O │     Agents share state ONLY via Task nodes   │
            │            └──────┬───────┘                                              │
            └───────────────────┼──────────────────────────────────────────────────────┘
                                │
                  ┌─────────────▼──────────────────────────────┐
                  │ FalkorDB                                   │
                  │  graph `strata`             (company brain)│
                  │  graph `strata_user_<id>`   (per-user mem.) │
                  │  vector + range indexes, graph algorithms   │
                  └────────────────────────────────────────────┘
```

Design rules that keep the graph load-bearing and the demo explainable:

- `backend/graph/service.py` is the **only** module that talks to FalkorDB. Every query is a named, parameterised template in `backend/graph/queries/*.cypher` (listed verbatim below).
- The LLM **never writes Cypher**. It extracts structure from a message, drafts diff text, or (only when intent is unclear) picks one of the vetted tools. Answer text is composed from graph results, never free-generated, so each sentence can carry the ids of its evidence.
- Staleness, supersession, ownership, expertise and bridges are all graph traversals and algorithms. Remove FalkorDB and none of them exist.

## Graph data model (graph `strata`)

### Temporal convention

All timestamps are epoch milliseconds. `valid_to` unset means *currently in force*. **"As of time T"** means `valid_from <= T AND (valid_to IS NULL OR valid_to > T)`. `recorded_at` is when Strata learned the fact. Superseding **closes** (`valid_to`) and adds a `SUPERSEDES` edge; nothing is ever deleted, which is what makes time travel a re-run of the same query with a different `$t`.

### Nodes

| Label | Key properties |
|---|---|
| `Person` | `id`, `name`, `handle`, `role` |
| `Team` | `id`, `name` |
| `System` | `id`, `name`, `kind` |
| `Doc` | `id`, `title`, `url`, `kind` (readme, adr, onboarding, runbook), `version`, `updated_at`, `change_note` |
| `Ticket` | `id`, `title`, `status` (open, closed), `url`, `created_at` |
| `Message` | `id`, `channel`, `text`, `ts` |
| `PR` | `id`, `title`, `status`, `merged_at`, `url` |
| `Chunk` | `id`, `text`, `source_id`, `embedding` (vector, cosine) |
| `Decision` | `id`, `summary`, `rationale`, `valid_from`, `valid_to`, `recorded_at`, `confidence` |
| `Claim` | `id`, `text`, `valid_from`, `valid_to`, `recorded_at` |
| `Task` | `id`, `kind` (`drift_fix`, `review`), `status` (`open`, `approved`, `rejected`, `in_progress`, `done`), `draft`, `created_by_agent`, `created_at`, `updated_at` |
| `Agent` | `id`, `name` (Ingestor, Steward, Concierge) |

### Relationships

| Pattern | Meaning |
|---|---|
| `(Person)-[:MEMBER_OF]->(Team)` | org structure |
| `(Team)-[:OWNS]->(System)`, `(Person)-[:OWNS]->(Doc\|Ticket)` | ownership |
| `(Person)-[:AUTHORED {ts}]->(Doc\|PR\|Message\|Ticket)`, `(Person)-[:REVIEWED {ts}]->(PR)` | activity (drives expertise) |
| `(Doc\|Ticket\|PR\|Message)-[:ABOUT]->(System)`, `(Claim)-[:ABOUT]->(System)` | topic / scope |
| `(Decision)-[:DECIDED_BY]->(Person)`, `(Decision)-[:AFFECTS]->(System)` | accountability, scope |
| `(Decision)-[:SUPERSEDES {ts}]->(Decision)` | decision lineage |
| `(Decision)-[:ESTABLISHES]->(Claim)` | a decision implies facts |
| `(Doc\|Ticket)-[:ASSERTS]->(Claim)`, `(Doc\|Ticket)-[:CITES]->(Decision)` | the **drift hooks** |
| `(Decision\|Claim)-[:EVIDENCED_BY]->(Message\|Doc\|Chunk)` | provenance |
| `(Doc\|Message)-[:HAS_CHUNK]->(Chunk)` | retrieval |
| `(Person)-[:COLLABORATES {weight}]->(Person)` | derived, symmetric: shared PRs and docs |
| `(Task)-[:CONCERNS]->(Doc\|Ticket)`, `(Task)-[:CAUSED_BY]->(Decision)`, `(Task)-[:ASSIGNED_TO]->(Person)` | drift task |
| `(Agent)-[:CREATED]->(Task)`, `(Task)-[:HANDED_TO {ts}]->(Agent)` | coordination |
| `(Doc\|Ticket)-[:NEXT_VERSION]->(Doc\|Ticket)` | an approved fix creates a new version; the old one is kept |

Decision and claim `valid_to` are closed by the **same real `supersede` query** both for the three historical reversals in the seed data and for the live one.

### Personal memory graph (`strata_user_<id>`)

`(:Session)-[:ASKED]->(:Question)-[:SHOWN]->(:DecisionRef {decision_id, system_id, valid_from_at_time})`. At session start the backend compares each remembered `DecisionRef` with the decision now in force in `strata` and reports changes: *"Since you last asked about the event bus, that decision changed on Oct 16."* Each user has an isolated FalkorDB graph; state is durable across restarts.

### Indexes

```cypher
CREATE INDEX FOR (p:Person) ON (p.id)   -- also System, Decision, Claim, Doc, Ticket, Task, Message on (id), Task on (status)
CREATE VECTOR INDEX FOR (c:Chunk) ON (c.embedding) OPTIONS {dimension: 384, similarityFunction: 'cosine'}
```

## Cypher queries and graph algorithms the product depends on

Each query below is the exact file in `backend/graph/queries/`. The FalkorDB algorithm procedures (`algo.pageRank`, `algo.betweenness`, `algo.labelPropagation`) were verified against the running server's `dbms.procedures()`.

### Q1 · `find_entry_points_vector` — semantic entry points (vector index)
```cypher
// Q1a find_entry_points (semantic): top-k chunks nearest the question vector, with the doc/message each belongs to.
CALL db.idx.vector.queryNodes('Chunk', 'embedding', 8, vecf32($qvec)) YIELD node, score
MATCH (src)-[:HAS_CHUNK]->(node)
RETURN src.id AS src_id, labels(src)[0] AS src_label, node.id AS chunk_id, node.text AS text, score
ORDER BY score
```

### Q2 · `why` — decision in force as of T, lineage, evidence
```cypher
// Q2 why: the decision in force for a system as of time $t, who decided, what it superseded (lineage), what replaced it later, and evidence.
MATCH (s:System {id: $system_id})<-[:AFFECTS]-(d:Decision)
WHERE d.valid_from <= $t AND (d.valid_to IS NULL OR d.valid_to > $t)
OPTIONAL MATCH (d)-[:DECIDED_BY]->(p:Person)
OPTIONAL MATCH (d)-[:EVIDENCED_BY]->(ev) WHERE NOT ev:Chunk
OPTIONAL MATCH (newer:Decision)-[:SUPERSEDES]->(d)
OPTIONAL MATCH lineage = (d)-[:SUPERSEDES*1..5]->(old:Decision)
RETURN d.id AS decision_id, d.summary AS summary, d.rationale AS rationale, d.valid_from AS valid_from, d.valid_to AS valid_to,
       p.id AS decided_by, p.name AS decided_by_name,
       collect(DISTINCT {id: ev.id, kind: labels(ev)[0], text: coalesce(ev.text, ev.title)}) AS evidence,
       collect(DISTINCT {id: newer.id, summary: newer.summary, valid_from: newer.valid_from}) AS superseded_by,
       collect(DISTINCT [n IN nodes(lineage) | n.id]) AS lineage
```

Supporting: `decisions_by_ids` returns summary, rationale, owner and evidence for each decision on the lineage path.
```cypher
// decisions_by_ids: summary, rationale, owner and evidence for a set of decisions (lineage and superseded-by).
MATCH (d:Decision) WHERE d.id IN $ids
OPTIONAL MATCH (d)-[:DECIDED_BY]->(p:Person)
OPTIONAL MATCH (d)-[:EVIDENCED_BY]->(ev) WHERE NOT ev:Chunk
RETURN d.id AS id, d.summary AS summary, d.rationale AS rationale, d.valid_from AS valid_from, d.valid_to AS valid_to,
       p.id AS decided_by, p.name AS decided_by_name,
       collect(DISTINCT {id: ev.id, kind: labels(ev)[0], text: coalesce(ev.text, ev.title), url: ev.url}) AS evidence
```

### Q3 · `supersede` — close, never delete
```cypher
// Q3 supersede: close the old decision and its claims at the new decision's start. Nothing is deleted.
MATCH (new:Decision {id: $new_id}), (old:Decision {id: $old_id})
SET old.valid_to = new.valid_from
MERGE (new)-[:SUPERSEDES {ts: new.valid_from}]->(old)
WITH old, new
OPTIONAL MATCH (old)-[:ESTABLISHES]->(c:Claim) WHERE c.valid_to IS NULL
SET c.valid_to = new.valid_from
RETURN old.id AS old_id, new.id AS new_id, collect(c.id) AS closed_claims
```

### Q4 · `whats_stale` — everything now contradicting reality
```cypher
// Q4 whats_stale: every Doc and open Ticket that asserts a closed claim or cites the superseded decision.
MATCH (new:Decision {id: $new_id})-[:SUPERSEDES]->(old:Decision)
MATCH (item)-[r:ASSERTS|CITES]->(x)
WHERE (x = old OR (old)-[:ESTABLISHES]->(x)) AND NOT (item)-[:NEXT_VERSION]->()
  AND (item:Doc OR (item:Ticket AND item.status = 'open'))
RETURN DISTINCT item.id AS item_id, labels(item)[0] AS item_label, item.title AS title, type(r) AS how,
       x.id AS stale_id, coalesce(x.text, x.summary) AS stale_text
ORDER BY item_label, item_id
```

### Q5 · `route_to_owner` — accountable owner
```cypher
// Q5 route_to_owner: direct owner if any; otherwise the owning team of the item's system (caller picks top expert via who_knows).
MATCH (item {id: $item_id})
OPTIONAL MATCH (owner:Person)-[:OWNS]->(item)
OPTIONAL MATCH (item)-[:ABOUT]->(s:System)<-[:OWNS]-(t:Team)<-[:MEMBER_OF]-(m:Person)
RETURN owner.id AS owner_id, owner.name AS owner_name, s.id AS system_id, t.name AS team,
       collect(DISTINCT m.id) AS team_member_ids
```

If an item has no direct owner, the Steward picks the team member with the highest **Who Knows** score for that system (Q7), so every item gets an owner.

### Q6 · `create_drift_task`
```cypher
// Q6 create_drift_task: a Task for a stale item, caused by a decision, assigned to an owner, created by the Steward agent.
MATCH (item {id: $item_id}), (d:Decision {id: $decision_id}), (p:Person {id: $owner_id}), (a:Agent {name: 'Steward'})
CREATE (t:Task {id: $task_id, kind: 'drift_fix', status: 'open', draft: $draft, created_by_agent: 'Steward', created_at: $now, updated_at: $now})
CREATE (a)-[:CREATED]->(t), (t)-[:CONCERNS]->(item), (t)-[:CAUSED_BY]->(d), (t)-[:ASSIGNED_TO]->(p)
RETURN t.id AS task_id
```

### Q7 · `who_knows` — expertise = activity × (1 + PageRank), with a betweenness badge
```cypher
// Q7a who_knows (activity): authored/reviewed work on a system, per person.
MATCH (p:Person)-[r:AUTHORED|REVIEWED]->(w)-[:ABOUT]->(s:System {id: $system_id})
RETURN p.id AS person_id, p.name AS name, count(r) AS activity,
       sum(CASE WHEN type(r) = 'AUTHORED' THEN 1 ELSE 0 END) AS authored,
       sum(CASE WHEN type(r) = 'REVIEWED' THEN 1 ELSE 0 END) AS reviewed
ORDER BY activity DESC
```
```cypher
// Q7b PageRank over the collaboration graph: who the organisation's work flows through.
CALL algo.pageRank('Person', 'COLLABORATES') YIELD node, score
RETURN node.id AS person_id, score ORDER BY score DESC
```
```cypher
// Q7c Betweenness over the collaboration graph: people who bridge otherwise separate groups (knowledge bridges).
CALL algo.betweenness({nodeLabels: ['Person'], relationshipTypes: ['COLLABORATES']}) YIELD node, score
RETURN node.id AS person_id, score ORDER BY score DESC
```

Final score = normalised activity on the system × (1 + PageRank over the collaboration graph). Betweenness drives the **knowledge bridge** badge.

### Q8 · `informal_teams` — label propagation over collaboration
```cypher
// Q8 informal_teams: label-propagation communities of people who really work together (vs the org chart).
CALL algo.labelPropagation({nodeLabels: ['Person'], relationshipTypes: ['COLLABORATES']}) YIELD node, communityId
RETURN communityId AS community, collect(node.id) AS member_ids
```

### Q9 · `bus_factor`
```cypher
// Q9 bus_factor: systems where at most one person has meaningful (>= threshold) authored/reviewed activity.
MATCH (s:System)<-[:ABOUT]-(w)<-[r:AUTHORED|REVIEWED]-(p:Person)
WITH s, p, count(r) AS a
WHERE a >= $threshold
WITH s, collect({id: p.id, name: p.name, activity: a}) AS experts
WHERE size(experts) <= 1
RETURN s.id AS system_id, experts
```

### Q10 · `build_collaboration` — derive `COLLABORATES` after ingest
```cypher
// Q10 build_collaboration: derive symmetric COLLABORATES edges (both directions, weight = shared work items) after ingest.
MATCH (a:Person)-[:AUTHORED|REVIEWED]->(w)<-[:AUTHORED|REVIEWED]-(b:Person)
WHERE a.id < b.id AND NOT w:Message
WITH a, b, count(DISTINCT w) AS weight
MERGE (a)-[c:COLLABORATES]->(b) SET c.weight = weight
MERGE (b)-[c2:COLLABORATES]->(a) SET c2.weight = weight
RETURN count(*) AS pairs
```

### Q11 · `resume_tasks` — coordination durability
```cypher
// Q11 resume_tasks: open or in-progress tasks, their agents and causing decision, so work resumes after a restart.
MATCH (t:Task) WHERE t.status IN ['open', 'in_progress']
OPTIONAL MATCH (t)-[:HANDED_TO]->(a:Agent)
OPTIONAL MATCH (t)-[:CAUSED_BY]->(d:Decision)
RETURN t.id AS task_id, t.kind AS kind, t.status AS status, d.id AS decision_id, t.created_at AS created_at, collect(a.name) AS agents
ORDER BY created_at
```

### Drift Inbox: approval, history-preserving versions
```cypher
// inbox: drift tasks with the stale item, causing decision, replaced decision and accountable owner.
MATCH (t:Task {kind: 'drift_fix'})-[:CONCERNS]->(item), (t)-[:CAUSED_BY]->(d:Decision), (t)-[:ASSIGNED_TO]->(p:Person)
OPTIONAL MATCH (d)-[:SUPERSEDES]->(old:Decision)
RETURN t.id AS task_id, t.status AS status, t.draft AS draft, t.updated_at AS updated_at,
       item.id AS item_id, labels(item)[0] AS item_label, item.title AS item_title,
       d.id AS decision_id, d.summary AS decision_summary,
       old.id AS old_decision_id, old.summary AS old_summary,
       p.id AS owner_id, p.name AS owner_name
ORDER BY t.created_at, t.id
```
```cypher
// stale_reason: the graph path that makes a task's item stale (item -> closed claim / superseded decision).
MATCH (t:Task {id: $task_id})-[:CONCERNS]->(item)-[r:ASSERTS|CITES]->(x), (t)-[:CAUSED_BY]->(new:Decision)-[:SUPERSEDES]->(old:Decision)
WHERE x = old OR (old)-[:ESTABLISHES]->(x)
RETURN item.id AS item_id, type(r) AS how, x.id AS stale_id, coalesce(x.text, x.summary) AS stale_text, old.id AS old_decision_id, new.id AS new_decision_id
```
```cypher
// approve_doc: approving a drift task creates a new Doc version that asserts the new claim; the old version is kept.
MATCH (t:Task {id: $task_id, status: 'open'})-[:CONCERNS]->(old:Doc), (t)-[:CAUSED_BY]->(d:Decision)-[:ESTABLISHES]->(c:Claim)
WHERE NOT (old)-[:NEXT_VERSION]->()
CREATE (new:Doc {id: $new_id, title: old.title, url: old.url, kind: old.kind, version: old.version + 1, updated_at: $now, change_note: t.draft})
CREATE (old)-[:NEXT_VERSION]->(new), (new)-[:ASSERTS]->(c)
SET t.status = 'approved', t.updated_at = $now
RETURN new.id AS new_id
```
```cypher
// approve_ticket: like approve_doc, for an open Ticket (new version node, old one kept).
MATCH (t:Task {id: $task_id, status: 'open'})-[:CONCERNS]->(old:Ticket), (t)-[:CAUSED_BY]->(d:Decision)-[:ESTABLISHES]->(c:Claim)
WHERE NOT (old)-[:NEXT_VERSION]->()
CREATE (new:Ticket {id: $new_id, title: old.title, url: old.url, status: old.status, created_at: old.created_at, change_note: t.draft})
CREATE (old)-[:NEXT_VERSION]->(new), (new)-[:ASSERTS]->(c)
SET t.status = 'approved', t.updated_at = $now
RETURN new.id AS new_id
```
```cypher
// reject_task: the human declined the drafted fix; the item stays flagged as stale knowledge.
MATCH (t:Task {id: $task_id, status: 'open'})
SET t.status = 'rejected', t.updated_at = $now
RETURN t.id AS task_id
```
`copy_about` and `copy_owner` carry topic and ownership links onto the new version node.

### Ingest, agent hand-off, retrieval support
```cypher
// current_decisions: every decision still in force and the system it affects (grounds supersession detection).
MATCH (d:Decision)-[:AFFECTS]->(s:System) WHERE d.valid_to IS NULL
RETURN d.id AS id, d.summary AS summary, s.id AS system_id ORDER BY s.id
```
```cypher
// ingest_decision: record a chat message and the Decision + Claim it establishes, with provenance back to the message.
MATCH (s:System {id: $system_id}), (p:Person {id: $author_id})
CREATE (m:Message {id: $msg_id, channel: $channel, text: $text, ts: $ts})
CREATE (d:Decision {id: $decision_id, summary: $summary, rationale: $rationale, valid_from: $ts, recorded_at: $now, confidence: $confidence})
CREATE (c:Claim {id: $claim_id, text: $claim_text, valid_from: $ts, recorded_at: $now})
CREATE (p)-[:AUTHORED {ts: $ts}]->(m), (m)-[:ABOUT]->(s)
CREATE (d)-[:DECIDED_BY]->(p), (d)-[:AFFECTS]->(s), (d)-[:ESTABLISHES]->(c), (c)-[:ABOUT]->(s)
CREATE (d)-[:EVIDENCED_BY]->(m), (c)-[:EVIDENCED_BY]->(m)
RETURN d.id AS decision_id
```
```cypher
// add_message_chunk: embedded chunk of a message, linked for retrieval and as decision evidence.
MATCH (m:Message {id: $msg_id}), (d:Decision {id: $decision_id})
CREATE (m)-[:HAS_CHUNK]->(c:Chunk {id: $chunk_id, text: m.text, source_id: m.id, embedding: vecf32($vec)})
CREATE (d)-[:EVIDENCED_BY]->(c)
```
```cypher
// create_pipeline_task: the coordination Task for one ingest run; agents hand it to each other through the graph.
MATCH (a:Agent {name: 'Ingestor'}), (d:Decision {id: $decision_id})
CREATE (t:Task {id: $task_id, kind: 'review', status: 'in_progress', draft: $summary, created_by_agent: 'Ingestor', created_at: $now, updated_at: $now})
CREATE (a)-[:CREATED]->(t), (t)-[:CAUSED_BY]->(d)
RETURN t.id AS task_id
```
```cypher
// handoff_task: hand a Task to an agent (durable coordination state) and set its status.
MATCH (t:Task {id: $task_id}), (a:Agent {name: $agent})
CREATE (t)-[:HANDED_TO {ts: $now}]->(a)
SET t.status = $status, t.updated_at = $now
RETURN t.id AS task_id
```
```cypher
// agent_timeline: creation and handoff events for every task, oldest first, for the Agents timeline.
MATCH (t:Task)
OPTIONAL MATCH (t)-[h:HANDED_TO]->(a:Agent)
OPTIONAL MATCH (c:Agent)-[:CREATED]->(t)
RETURN t.id AS task_id, t.kind AS kind, t.status AS status, c.name AS created_by, t.created_at AS created_at,
       collect(CASE WHEN a IS NULL THEN NULL ELSE {agent: a.name, ts: h.ts} END) AS handoffs
ORDER BY t.created_at, t.id
```
```cypher
// systems_of_sources: the systems that retrieved docs/messages are about (turns entry points into a topic).
MATCH (s)-[:ABOUT]->(sys:System) WHERE s.id IN $ids
RETURN s.id AS src_id, sys.id AS system_id
```
```cypher
// person_work: the concrete work items (sources) that make a person an expert on a system.
MATCH (p:Person {id: $person_id})-[r:AUTHORED|REVIEWED]->(w)-[:ABOUT]->(s:System {id: $system_id})
RETURN w.id AS id, labels(w)[0] AS kind, coalesce(w.title, w.text) AS text, w.url AS url, type(r) AS how
ORDER BY coalesce(r.ts, 0) DESC LIMIT 6
```
```cypher
// person_collab_teams: which teams a person's collaborators belong to (explains a knowledge bridge).
MATCH (p:Person {id: $person_id})-[c:COLLABORATES]->(o:Person)-[:MEMBER_OF]->(t:Team)
RETURN t.name AS team, count(DISTINCT o) AS people, sum(c.weight) AS weight
ORDER BY weight DESC
```

### Graph panel and personal memory
```cypher
// graph_view: decision/claim/doc/ticket/evidence structure for the graph panel; the UI dims anything closed or not yet true as of the chosen time.
MATCH (a)-[r:AFFECTS|DECIDED_BY|SUPERSEDES|ESTABLISHES|ASSERTS|CITES|NEXT_VERSION|EVIDENCED_BY]->(b)
WHERE NOT a:Chunk AND NOT b:Chunk AND NOT (a:Claim AND type(r) = 'EVIDENCED_BY')
RETURN a.id AS src, labels(a)[0] AS src_label, coalesce(a.title, a.summary, a.text, a.name) AS src_name, a.valid_from AS src_from, a.valid_to AS src_to, a.status AS src_status,
       b.id AS dst, labels(b)[0] AS dst_label, coalesce(b.title, b.summary, b.text, b.name) AS dst_name, b.valid_from AS dst_from, b.valid_to AS dst_to, b.status AS dst_status,
       type(r) AS type, r.ts AS ts
```
```cypher
// p_record_question: personal memory (graph strata_user_<id>): a session asked a question.
MERGE (s:Session {id: $sid}) ON CREATE SET s.started_at = $now
CREATE (q:Question {id: $qid, text: $text, ts: $now})
CREATE (s)-[:ASKED]->(q)
```
```cypher
// p_record_shown: personal memory: which decision version a question was shown.
MATCH (q:Question {id: $qid})
CREATE (q)-[:SHOWN]->(:DecisionRef {decision_id: $decision_id, system_id: $system_id, valid_from_at_time: $valid_from})
```
```cypher
// p_last_shown: latest decision version shown to this user per system, with the question that showed it.
MATCH (q:Question)-[:SHOWN]->(r:DecisionRef)
WITH r.system_id AS system_id, q, r ORDER BY q.ts DESC
RETURN system_id, collect(r.decision_id)[0] AS decision_id, collect(q.text)[0] AS question, max(q.ts) AS last_ts
```

Small lookups (`people`, `systems`, `team_of`, `item_text`, `count_nodes`) are in the same folder.

## Features

- **Ask Why** — natural-language question → the decision in force, who made it, the full `SUPERSEDES` chain and original evidence. The graph path is highlighted in the panel and every sentence links to its sources. With no supporting evidence: *"I don't know"* plus what was searched.
- **Drift Inbox** — on a new decision: detect what it supersedes → close old decision and claims → traverse to every `Doc`/open `Ticket` that asserts or cites them → route to an owner → draft a diff → **Approve / Reject**. Approve creates a new version node; reject leaves the item flagged.
- **Who Knows / bus factor** — ranked people with a visible score breakdown (activity, PageRank, betweenness); single-point-of-knowledge warnings; knowledge bridges; informal teams that differ from the org chart.
- **Time travel** — the slider re-runs the same Cypher with a different `$t`; closed decisions dim (they do not vanish) and the "why" answer flips.
- **Personal memory** — per-user graphs; "since you last asked, that changed".
- **Agents coordinating through the graph** — Ingestor, Steward and Concierge share state only via `Task` nodes. A run interrupted by a restart is finished by `resume` from task status (covered by a test).

## Why the graph is load-bearing

Take FalkorDB out and these stop existing: supersession and as-of answers (`why`, `supersede`), staleness (`whats_stale` traverses `ASSERTS`/`CITES` into a closed claim), ownership routing, expertise (PageRank, betweenness, label propagation over `COLLABORATES`), bus-factor detection, provenance paths, agent hand-offs (`Task` nodes), and per-user memory graphs. The UI's highlighted path is the exact path the query returned.

## Honesty

- **Demo data is synthetic.** Northwind Labs is fictional and generated deterministically (`data/generate.py`, fixed seed) and is labelled as synthetic in the UI. Storyline beats (a session-storage reversal, a CI migration, an API deprecation, one bus-factor system, one knowledge bridge, one cross-team cluster) are written into the generator so every demo is reproducible. The live reversal message is **not** in the seed data; it is ingested through the real pipeline.
- **What is LLM-driven:** (1) extraction of a decision from a message, grounded in the decisions currently in force so "what does this supersede?" can only pick a real node; (2) drafting the fix diff; (3) a fallback router used only when question intent is unclear. Everything else, including staleness, owners, expertise, lineage and the text of every answer, comes from graph queries.
- **Provenance:** every answer sentence lists the ids of its evidence (messages, docs, PR/doc items). If the graph has none, Strata says *"I don't know"* and shows what it searched.
- **Human approval:** drafted fixes are open tasks. Approve creates a new version; the old version stays. Reject keeps the item flagged. Nothing is applied automatically.
- **LLM provider:** the default provider shells out to the local Claude Code CLI, which is why a hosted deployment of the AI path needs that CLI. LLM responses are cached on disk by prompt hash (`backend/.llm_cache`, git-ignored) so recorded demos are reproducible. A cached replay is a replay of a real earlier model response, and is disclosed here rather than presented as a live call.
- **Known limits:** retrieval-based topic matching uses a distance threshold tuned on the demo corpus; expertise scores count all authored/reviewed items on a system, including messages and tickets; the as-of parser understands "as of <month>" and the slider.
